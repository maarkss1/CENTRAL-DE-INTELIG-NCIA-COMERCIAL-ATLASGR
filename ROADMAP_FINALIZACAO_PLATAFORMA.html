O que precisava ser acrescentado

Achados que o roadmap antigo não tratava com dono, prova e gate claros.

P0 · BOOT / AUTH

Reset emergencial no caminho normal de start

npm start chama scripts/emergency-reset-all-passwords.ts antes do servidor. O script é inerte sem a env, mas se ela ficar configurada pode redefinir as credenciais de todos, revogar sessões e marcar troca obrigatória. Deve virar operação one-shot, fora do boot normal.

P0 · VERDADE DO GATE

CI/status precisa pertencer ao repositório correto

O Coordenador deve inventariar checks e ambientes vinculados e bloquear contaminação por projeto/serviço externo. Gate ausente ou de outro projeto não pode ser contado como evidência deste release.

P1 · UI COMPARTILHADA

Issue #242: Dialog fechado pode aparecer

Dialog.tsx aplica flex ao <dialog> fechado. Como é componente compartilhado, a correção exige regressão nos consumidores e entra na onda de jornada comercial/UX.

P1 · MAIN EM MOVIMENTO

Go-Live não encerrou evolução

Há trabalho posterior ao RC, incluindo Market Intelligence, arquitetura, integrações, acessibilidade e Cockpit Comercial. O novo processo trata release como checkpoint e adiciona hardening e smoke final sobre a main atual.

P2 · MARKET INTELLIGENCE

Onda própria para decisão territorial

Território, CNPJ, concorrência, White Space, Hub Suitability e economics precisam de fonte, versão, proveniência e gate fail-closed antes de recomendar contratação de vendedor.

P2 · API / CONTRATOS

Documentação que quebra quando envelhece

verify:openapi-drift já existe. O roadmap passa a exigir OpenAPI e tipos compartilhados como gate, em vez de tratar documentação como evidência de implementação.

GATE EXISTENTE

Harness real aproveitado

O projeto já possui unit, integration, E2E, build, verify:integrations, verify:ai, verify:prod, ZAP, Trivy, audit waivers e golden evaluation. As ondas agora dizem quando cada gate entra.

PÓS-RELEASE

Hypercare, rollback e prova de persistência

A última onda valida smoke real, banco, tenant, PII, observabilidade, migração e rollback. “A tela abriu” deixa de ser critério suficiente.

Regras de execução

Estas regras valem mais que a pressa. Concorrência sem isolamento produz um castelo de cartas com CI verde por acidente.

Worktree + branch por especialista. Nenhum agente paralelo compartilha checkout vivo.

Matriz antes de disparar. Arquivos compartilhados recebem dono único antes do primeiro commit.

Gate a cada 2–3 merges. Não acumular a onda inteira antes de testar a integração.

01 e 01A são o mesmo slot. Nunca executar simultaneamente por causa de schema/migrations.

06 e 06A são o mesmo slot. Extrações entram depois que Integrações libera a propriedade compartilhada.

Teste não executado = BLOCKED. “Limitação do ambiente” só existe depois de reprodução e evidência.

Sem verdade cenográfica. Mock, faker, número plausível e fallback sintético nunca são fato operacional.

Persistência precisa ser provada. Em ação crítica, confirmar banco e tenant, não apenas UI ou HTTP 200.

Release é binário. APPROVED ou BLOCKED; sem “aprovado com ressalva bloqueante”.

Roster real e função de cada agente

Agentes 19/20 não são usados. Verificação contínua é 14 + 08; experiência real é 02 + 03 + 08 + 14, acionando 01A/15 para persistência e PII quando necessário.
