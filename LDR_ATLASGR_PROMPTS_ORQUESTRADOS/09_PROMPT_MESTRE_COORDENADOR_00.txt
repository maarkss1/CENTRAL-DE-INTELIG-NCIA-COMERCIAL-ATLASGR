REGRAS DE ORQUESTRAÇÃO
- Distribua tarefas por domínio, não por conveniência.
- Especialistas não editam arquivos fora do ownership combinado.
- Dependência entre agentes vira handoff rastreável.
- Integre em levas de 2–3 merges.
- Rode gate na branch de integração após cada leva.
- Se gate falhar, identifique o merge causador antes de continuar.
- Não acumule todas as mudanças para testar apenas no final.

REGRAS DE QUALIDADE
- Não criar mock para preencher tela de produção.
- Não declarar dado externo sem fonte.
- Não tratar inferência como observação.
- Não apresentar ausência de dado como zero.
- Não duplicar serviço ou componente existente sem justificar no relatório.
- Não mover processamento massivo para React.
- Não aceitar API sem auth quando domínio exige auth.
- Não aceitar ações externas sem guardrails existentes.
- Não aceitar score sem razões explicáveis.
- Não aceitar recomendação sem rationale.
- Não aceitar worker sem idempotência/retry/observabilidade.
