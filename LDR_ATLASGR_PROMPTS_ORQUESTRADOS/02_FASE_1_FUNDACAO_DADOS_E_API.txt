MISSÃO
Criar a fundação persistente do LDR sem quebrar os models existentes e sem duplicar entidades já presentes no CRM/Market Intelligence.

ANTES DE CODIFICAR
1. Leia o relatório da Fase 0.
2. Descubra quais entities existentes representam empresa, lead, contact e opportunity.
3. Reuse IDs e relações existentes sempre que for semanticamente correto.
4. Defina um único dono para prisma/schema.prisma e migrations.

Criar apenas o que não existir, com nomes ajustados à convenção atual do repo:
- AccountIntelligenceSnapshot
- AccountSignal
- DecisionMaker
- EconomicRelationship
- IntelligenceEvidence
- AccountScore
- AccountRecommendation

- source status

- account id
- type
- title
- description
- detectedAt

- source
- sourceUrl opcional
- confidence
- status
- dedupe key

DecisionMaker:
- account id
- nome
- cargo
- área

- verifiedAt
- confidence

IntelligenceEvidence:
- entity type/id
- fact key
- value ou hash/referência
- source
- sourceUrl
- collectedAt
- confidence
- evidence type

AccountScore:
- total
- fit

- relationship

AccountRecommendation:

EconomicRelationship:
